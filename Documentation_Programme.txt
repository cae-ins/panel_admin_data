Programme PANEL ADMIN 

ÉTAPE 0 : Upload des sources vers MinIO (Staging)

Cette étape du programme consiste à charger les données locales vers le serveur MinIO, dans l’environnement de staging, en vue de leur traitement ultérieur. Plus précisément, le script permet d’organiser et de transférer les fichiers selon deux catégories distinctes. D’une part, les fichiers de référence, comprenant : le fichier des codes ANSTAT et la table de correspondance des emplois.
Ces fichiers sont stockés dans un répertoire dédié intitulé "references". D’autre part, les fichiers de soldes mensuels, sont chargés dans un dossier spécifique destiné aux données mensuelles.

ÉTAPE 1 : PRÉ-ANALYSE DES COLONNES

Le programme lit et analyse automatiquement les fichiers Excel stockés dans le bucket MinIO staging plus spécifiquement les fichiers mensuels uniquempent afin de préparer les données pour les étapes suivantes du pipeline. Il effectue les opérations suivantes :

Connexion et récupération des fichiers : le script se connecte à MinIO et liste tous les fichiers Excel mensuels présents dans le dossier fichiers_mensuels.
Extraction des en-têtes : pour chaque fichier,
il lit uniquement les noms de colonnes des deux feuilles : Feuille 1 (F1) : données des agents; Feuille 2 (F2) : codes numériques liés aux emplois
il extrait également tous les codes numériques présents dans F2.
Analyse des changements entre périodes :
Le programme compare les colonnes et codes d’une période à l’autre afin de détecter : les colonnes apparues ou disparues dans F1 ainsi que les codes numériques ajoutés ou supprimés dans F2
Statistiques globales : il calcule le nombre de colonnes et de codes uniques par feuille et fournit les valeurs min, max et moyenne pour chaque période.

Génération de rapports : les résultats sont sauvegardés au format CSV dans le dossier pre_analyse de MinIO, notamment : colonnes_f1_uniques.csv; codes_f2_uniques.csv; stats_par_periode.csv; changements_f1.csv; changements_codes_f2.csv

Cette pré-analyse permet de détecter toute incohérence ou évolution structurelle des fichiers Excel avant leur intégration dans le pipeline de traitement (bronze). Elle fournit également une documentation claire des colonnes et codes pour les équipes de traitement des données.

ÉTAPE 2 : STAGING → BRONZE PARQUET

Ce programme correspond à la deuxième étape du pipeline de traitement des données du panel administratif. Il a pour objectif de transformer les fichiers Excel bruts stockés dans l’espace de stockage staging en fichiers au format Parquet, enregistrés dans le bucket bronze. 

Dans un premier temps, le script établit une connexion au serveur MinIO et récupère l’ensemble des fichiers Excel mensuels présents dans le répertoire dédié. Chaque fichier est ensuite traité individuellement afin d’assurer une ingestion fiable et continue, même en cas d’erreur sur certains fichiers.
Pour chaque fichier, le programme lit les deux feuilles principales. La première feuille contient les données relatives aux agents, tandis que la seconde regroupe des informations sous forme de codes numériques. Le script détecte automatiquement la ligne d’en-tête afin de s’adapter aux variations de structure entre les fichiers.
Une fois les données chargées, les noms de colonnes sont normalisés. Cette normalisation consiste à convertir les noms en majuscules, supprimer les caractères spéciaux et les accents, et remplacer les séparateurs par des underscores. Les éventuels doublons de noms de colonnes sont également traités afin de garantir l’unicité des champs.
Lorsque cela est possible, une jointure est effectuée entre les deux feuilles à l’aide d’une clé commune, telle que le matricule ou une clé composite. Cette opération permet d’enrichir les données principales avec les informations issues des codes numériques. Par la suite, le programme ajoute des métadonnées à chaque enregistrement, notamment la période correspondant au fichier traité ainsi que le nom du fichier source. Toutes les colonnes sont ensuite converties en type texte, conformément au principe du niveau bronze, qui consiste à conserver des données brutes sans transformation métier.

Les données ainsi préparées sont ensuite sérialisées au format Parquet, un format optimisé pour le stockage et les traitements analytiques. Un fichier Parquet est généré pour chaque période et stocké dans le bucket bronze sur MinIO. Enfin, le programme gère les éventuelles erreurs sans interrompre l’exécution globale et affiche un résumé indiquant le nombre de fichiers traités avec succès ainsi que le nombre d’échecs. En résumé, cette étape permet de standardiser techniquement les données issues des fichiers Excel, de les convertir dans un format parquet et de les préparer pour les transformations métier qui seront réalisées lors de l’étape suivante du pipeline, appelée Silver.


ÉTAPE 3 : BRONZE VERS SILVER

Cette étape constitue le cœur du traitement métier du pipeline du panel administratif. Elle consiste à transformer les données brutes stockées dans la couche bronze en données enrichies, structurées et prêtes pour l’analyse, qui seront stockées dans la couche silver.

Le programme commence par se connecter au serveur MinIO et charge les différentes tables de référence ANSTAT disponibles dans l’espace staging. Ces tables contiennent les correspondances entre les libellés métiers (organisme, emploi, grade, etc.) et leurs codes normalisés. Chaque table est préparée en normalisant les libellés afin de faciliter les opérations de rapprochement avec les données sources.
Ensuite, le script parcourt l’ensemble des fichiers Parquet présents dans la couche bronze, chaque fichier correspondant à une période mensuelle. Pour chaque fichier, les données sont chargées puis les noms de colonnes sont harmonisés à l’aide d’un mapping basé sur des règles de reconnaissance (expressions régulières). Cette étape permet de standardiser les structures issues de sources hétérogènes.

Le programme impose également une cohérence temporelle en reconstruisant la variable de période (mois_annee) à partir du nom du fichier, afin d’éviter les incohérences éventuelles présentes dans les données initiales.

Une transformation importante concerne la variable de situation administrative. Celle-ci est normalisée en catégories homogènes, puis un filtrage est appliqué pour ne conserver que les situations pertinentes pour l’analyse, notamment les agents en activité, en régularisation d’indemnités ou en demi-solde.

L’étape suivante consiste à enrichir les données à l’aide des tables ANSTAT. Pour chaque dimension (organisme, emploi, grade, service, fonction, etc.), une jointure est réalisée entre les données et les tables de référence après normalisation des libellés. Cela permet d’associer à chaque observation un code standardisé.

Par ailleurs, le programme calcule un indicateur de qualité des données : le taux de correspondance (matching) entre les libellés des données et les codes ANSTAT. Ce taux est calculé pour chaque période et pour plusieurs dimensions clés, notamment le code organisme, le code grade et le code emploi. Ces informations sont enregistrées dans un rapport CSV afin de suivre la qualité de l’enrichissement au fil du temps.

En complément, les variables monétaires et certains champs numériques sont convertis en type numérique afin de permettre des analyses quantitatives fiables dans les étapes ultérieures.

Les données traitées sont ensuite regroupées par année, puis concaténées pour produire un fichier unique par année au format Parquet. Ces fichiers sont enregistrés dans la couche silver sur MinIO.

Enfin, le programme génère un rapport récapitulatif indiquant le nombre de périodes traitées, les éventuelles erreurs rencontrées et les fichiers produits.

En résumé, cette étape permet de passer de données brutes à des données nettoyées, structurées et enrichies selon des règles métier. Elle garantit également un suivi de la qualité des correspondances avec les référentiels ANSTAT, constituant ainsi une base solide pour les analyses avancées et les étapes ultérieures du pipeline.
